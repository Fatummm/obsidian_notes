#sort 
англ. - "Radix sort"
**Time Complexity:** $O(d(n+b))$
$b$ - основание системы счисления 
$d$ - длина наибольшего числа в этой системе счисления
**Space Complexity:** $O(n+b)$
**Стабильность:** Стабильная(иначе бы не работала)
## 🔶Идея
А давайте попробуем не сортировать числа сразу, а опуститься на уровень ниже - сравнивать **разряды** чисел последовательно.

Идём от младшего разряда к старшему(LSD) и на каждой итерации сравниваем числа по их $i$-ому разряду

Если мы хотим отсортировать элементы лексикографически, то идём от старшего разряда - к младшему(MSD)

В случае десятичной системы счисления(и LSD):

**Step 1:** создаём "бакеты" - 10 массивов, каждый соответствует своему числу - от 0 до 9, соответственно. Затем пробегаемся по исходному массиву, и пихаем их в тот бакет, которому соответствует их разряд единиц. Затем последовательно проходимся по нашим бакетам, "выгружая" элементы в исходный массив. Главное - "выгружать" их в таком порядке, в каком они были добавлены в бакет - **свойство стабильности**.

**Step 2:** аналогично создаём 10 пустых ведёрок, так же проходимся по массиву, но числа сравниваем уже с рязрядом десятков. Тут и на следующих шагах нам помогает свойство стабильности: если на текущем разряде числа равны, (например, мы сравниваем десятки, и рассматриваем числа 24 и 29), то, записав их в порядке, в котором они лежали на предыдущем шаге, мы не терям стабильность по первым i разрядам

**Step i:** продолжаем шаги до тех пор, пока не закончатся разряды у наибольшего числа(или, если мы знаем размер хранимых чисел, до наибольшего возможного числа)

## 🔶Реализация
### 🔸LSD
```cpp title="RadixSort(LSD)"
#include <iostream>
#include <algorithm>
#include <queue>
#include <random>
#include <chrono>

  
void radixSort(std::vector<int>& a, int n, int base = 256) {
	int mx = *std::max_element(a.begin(), a.end());
	int exp = 1;
	while (exp <= mx) {
		std::vector<std::vector<int>> buckets(base);
		// filling buckets(LSD)
		for (int i = 0 ; i != a.size(); ++i) {
			buckets[a[i] / exp % base].push_back(a[i]);
		}
  
		// filling an array
		auto it = a.begin();
		for (int i = 0; i != base; ++i) {
			for (int j = 0; j != buckets[i].size(); ++j) {
				*it = buckets[i][j];
				++it;
			}
		}
  
		// Debug cout
		std::cout << "Sort by " << exp << ": ";
		for (int i = 0; i != a.size(); ++i) {
			if (i != 0) std::cout << ' ';
			std::cout << a[i];
		} std::cout << '\n';
		  
		// move to other digit
		exp *= base;
	}
}
  
int main() {
	std::vector<int> a = {10, 1, 31, 200, 34, 25, 78, 160, 11, 99};
	radixSort(a, 10, 10);
	for (int i = 0; i != 10; ++i) {
		if (i != 0) std::cout << ' ';
		std::cout << a[i];
	} std::cout << '\n';
	// -3 1 2 3 4 4 5 6 7 11
}
```

## 🔶Оценка сложности
Посмотрим, что мы вообще делаем в нашей сортировке. Цикл `while` отвечает за перебор разрядов и совершит столько итераций, сколько разрядов наибольшем числе в массиве(с учётом выбранной системы счисления), обозначим это количество за $d$. Первый внутренний цикл `for` проходится по исходному массиву - $O(n)$. Второй цикл проходится по вспомогательному массиву, размер которого равен основанию системы счисления, пусть будет $b$. Внутри второго `for`'а второй цикл суммарно вытащит все элементы массива, то есть суммарное количество его итераций - $O(n)$.
Имеем
**Time Complexity:** $O(d(n+b))$, где $d$ - длина наибольшего числа, $n$ - количество элементов, $b$ - основание системы счисления. 

Что у нас по памяти? Ну мы создаём $b$ массивов, суммарная длина которых равна $n$. Итого
**Space Complexity:** $O(n+b)$
### 🔸NOTA BENE
На практике мы вправе сами выбирать основание системы счисления(чаще всего берётся 256), а так же каждое число ограничено своей памятью, так что не может быть бесконечно большим. Поэтому иногда мы принимаем $d$ и $b$ за константы, и время работы нашей сортировки становится **квази-линейным**(почти линия, короче) - $O(n)$.
