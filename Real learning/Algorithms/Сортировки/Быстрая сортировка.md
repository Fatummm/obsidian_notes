#sort 
англ. - "Quick sort"
**Time Complexity:** $O(n\log n)$, **существует худший случай**
**Space Complexity:** $O(\log n)$ за рекурсивный вызов;
**Стабильность:** Нестабильная
## 🔶Идея
Давайте возьмём какой-нибудь элемент из массива(**опорный, pivot**), и разобьём массив на две части - те элементы, которые меньше либо равны выбранному, и те, которые больше выбранного

Пусть мы выбрали элемент. Как теперь разбивать массив на две части?
### 🔸Разбиение Ломуто
Идея примерно похожа на сортировку вставками, только мы ищем не минимальный элемент, а все элементы, которые меньше либо равны нашему выбранному, и пихаем их в начало массива

Для удобства меняем наш выбранный элемент с последним(в оригинале просто берём последний элемент), проходимся по массиву слева направо, сравнивая с последним.
### 🔸Разбиение Хоара
Идём с двух сторон к центру массива. 
Слева ищем первый элемент, больший выбранного.
Справа ищем первый элемент, меньший либо равный выбранному.
Меняем найденные элементы местами
Повторяем цепочку действий

Для удобства меняем выбранный элемент с первым(в оригинале просто берётся первый элемент)
### 🔸Худший случай
Впервые сталкиваемся с понятием "**Худший случай работы алгоритма**" - такие входные данные, на которых алгоритм совершит максимальное количество операций. 
В случае быстрой сортировки худший случай возникает, когда выбранный элемент - всегда наибольший / наименьший на выбранном отрезке. В таком случае наш наш полуинтервал $[l, r)$ разбивается на полуинтервалы $[l, r-1), [r,r)$ и $[l, l), [l+1, r)$ соответственно. В таком случае мы на каждом рекурсивном вызове на массиве длины $k$ решаем задачу для подмассива длины $0$ и $k-1$ соответсвенно.
Значит, сортировка всего массива займёт $n + (n-1) + (n-2) + \dots +1=\frac{n+1}{2}n=O(n^2)$, деградируем до квадрата
## 🔶Реализация
```cpp title=QuickSort
#include <stdio.h>
#include <stdlib.h>
#include <iostream>
#include <vector>
  
template <typename Iter>
Iter choosePivo(Iter start, Iter end) {
	return (start + (rand() % (end - start))); // random choice
	// return end - 1; // Lomuto partition
	// return start; // Hoar partition
}
  
template <typename Iter>
Iter lomutoPartition(Iter start, Iter end) {
	Iter pivo = choosePivo(start, end);
	std::swap(*pivo, *(end - 1));
	pivo = end - 1;
	Iter movable = start;
	for (Iter it = start; it < end; ++it) {
		if (*it <= *pivo) {
			std::swap(*it, *movable);
			++movable;
		}
	}
	return movable - 1;
}
  
template <typename Iter>
Iter hoarPartition(Iter start, Iter end) {
	Iter pivo = choosePivo(start, end);
	Iter left = start, right = end - 1;
	while (true) {
		while (left < end && *left <= *pivo) ++left;
		while (right >= start && *right > *pivo) --right;
		if (left >= right) break;
		std::swap(*left, *right);
	}
	std::swap(*pivo, *right);
	return pivo;
}
  
template <typename Iter>
void quick_sort(Iter start, Iter end) {
	if (end - start <= 1) return;
	Iter pivo = lomutoPartition(start, end);
	quick_sort(start, pivo);
	quick_sort(pivo + 1, end);
}
  
int main() {
	std::vector<int> v = {1, 0, 4, 2, 31, 2, 4, 7, 9, -3};
	quick_sort(v.begin(), v.end());
	for (int i = 0; i != v.size(); ++i) {
		std::cout << v[i] << ' ';
	}
}
```
## 🔶Оценка сложности
Для начала рассмотрим лучший случай - когда выбранный элемент после распределения всегда оказывается в середине массива. Тогда сложность алгоритма будет задаваться рекуррентным соотношением 
$$T(n) = 2T\left( \frac{n}{2} \right) + \Theta(n) \implies /\text{по мастер-теореме}/ \implies T(n)=n\lg{n}$$
Средний же случай рассматривать сложно, но нетрудно показать, что чаще всего он ближе к наилучшему.
Допустим, мы своим разбиением всегда делим массив в отношении 9 : 1, тогда сложность будет описываться рекуррентно так:
$$T(n) = T\left( \frac{9n}{10} \right) + T\left( \frac{n}{10} \right) + \Theta(n)$$
Даже это оценивать сложно, но мы попробуем. Сначала построим дерево вызовов. Заметим, что все появляющиеся "маленькие" отрезочки мы заканчиваем обрабатывать на уровне примерно $\log_{10}{n}$. Если же мы будем идти по самым "большим" отрезкам, то вызов рекурсии закончится на уровне $\log_{\frac{10}{9}}{n}$. При этом на каждом слое мы потратим либо $\Theta(n)$ операций, либо ещё меньше(когда мы пойдём ниже уровня $\log_{10}{n}$). Получаем асимптотику $O\left( n\log_{\frac{10}{9}}{n} \right)=O(n\log n)$ (логарифмы с разными основаниями отличаются на константу)

## 🔶Вывод
По сравнению с сортировкой слиянием, быстрая имеет худший случай, но он редко достижим(с условием взятия случайного опорного элемента) в реальной жизни, поэтому в индустрии используется чаще quicksort, к тому же константа при $n\log n$ меньше, чем при mergesort
