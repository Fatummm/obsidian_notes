#search 
англ. - "Ternary search"
условия: **входной набор данных разбит на две части: строго возрастающая и строго убывающая**(либо наоборот, убывающая и возрастающая).
**Time Complexity:** $O(\log n)$
**Space Complexity:** $O(1)$
## 🔶Идея
Пусть нам дана определённая функция $f(x)$ и мы знаем, что у неё на отрезке $[a, b]$ есть локальный минимум(причём, единственный). Наша задача - найти этот минимум. Что нам делать?

**Решение:** Разобьём отрезок на три равные части, и посмотрим значения функции на их пересечениях:
$$mid_{1}=\frac{a+b}{3}, mid_{2}=2 \cdot \frac{a+b}{3}$$
### 🔸1. $f(mid_{1}) > f(mid_{2})$
Теперь рассмотрим три случая - на каком из подотрезков мог находиться локальный минимум?
1. $[a, mid_{1}]$ - в таком случае на отрезках $[mid_{1}, mid_{2}]$ и $[mid_{2}, b]$ функция должна возрастать, но $f(mid_{1}) > f(mid_{2}) \implies$ противоречие, такого быть не может
2. $[mid_{1}, mid_{2}]$ - в принципе, такое возможно - если точка локального минимума ближе к правой границе(или при других обстоятельствах, я привёл просто пример)
3. $[mid_{2}, b]$ - в таком случае на подотрезках $[a, mid_{1}]$ и $[mid_{1}, mid_{2}]$ функция должна убывать, и наше неравенство выполняется
Получается, точка нашего локального минимума может находиться либо в $[mid_{1}, mid_{2}]$, либо в $[mid_{2}, b]$. Можем отбросить первую треть и заняться рассмотрением отрезка $[mid_{1}, b]$(аналогичным способом).

### 🔸2. $f(mid_{1}) < f(mid_{2})$
Аналогично, рассмотрим три возможных расположения точки локального минимума
1. $[a, mid_{1}]$ - тогда на остальных двух подотрезках функция возрастает, неравенство выполнено
2. $[mid_{1}, mid_{2}]$ - вполне вероятно
3. $[mid_{2}, b]$ - в таком случае функция должная убывать на первых двух подотрезках, неравнество не выполнено $\implies$ противоречие
### 🔸3. $f(mid_{1}) = f(mid_{2})$
Этот случай можно рассматривать отдельно, а можно впихнуть в любой из двух предыдущих. **Почему?** При условии, что функция строго монотонна в обеих частях, значения функци в двух точках могут быть равны только тогда, когда локальный экстремум лежит между этими двумя точками - в нашем случае $[mid_{1}, mid_{2}]$. Если отдельно это условие пропишем, то при равенстве значений мы сократим исходный рассматриваемый отрезок не в $\frac{3}{2}$ раз, а в $3$ раза.

## 🔶Реализация
Тут вместо набора входных данных я использовал функцию $f(x)=x^9-2x^8-3x^5$ на отрезке $[0, 4]$(функция непрерывная, все значения точек на отрезке просто невозможно сохранить, поэтому я храню формулу).
```cpp title="Ternary Search"
#include <iostream>
#include <cmath>
  
double function(double x) {
	return pow(x, 9) - 2 * pow(x, 8) - 3 * pow(x, 5);
}
  
double ternarySearch(double l, double r, double eps) {
	double mid1, mid2;
	while (r - l > eps) {
		mid1 = (r - l)/3 + l;
		mid2 = (r-l)/3 * 2 + l;
		if (function(mid1) >= function(mid2)) l = mid1;
		else r = mid2;
	}
	return (r + l) / 2;
}
  
int main() {
	double eps = 0.000'000'000'1;
	double point_of_extremum = ternarySearch(0.0, 4.0, eps);
	std::cout << "Point of local minimum function f(x) = x^9 - 2x^8 - 3x^5 on [0, 4] is: "; // 1.98944
	std::cout << point_of_extremum << '\n';
	std::cout << "Local minimum is: " << function(point_of_extremum) << '\n'; // -96.0835
}
```

## 🔶Оценка сложности
### 🔸Time Complexity
На каждой итерации мы делим наш отрезок на три части, и оставляем только две.
Значит, всего итераций будет выполнено $O\left( \log_{\frac{3}{2}}n \right)=O(\log n)$
Каждая итерация - $O(1)$. Значит,
**Time Complexity:** $O(\log n)$

### 🔸Space Complexity
Мы только две переменные заводим, так что 
**Space Complexity:** $O(1)$
Конечно, проведя аналогию с бинарным поиском, мы можем написать рекурсивный тернарный поиск, тогда сложность составит $O(\log n)$
