#search 
англ. - "Interpolation search"
условия: **отсортированный набор данных**, **рекомендуется равномерная распределённость элементов массива**
**Time Complexity:** $O(\log \log n)$
**Space Complexity:** $O(1)$
## 🔶 Идея
Давайте так же, как в бинарном поиске, делить массив на две части, но вместо деления на две равные части мы принимаем в рассмотрение **величину** значения элемента, и на его основе разделяем массив.
**Пример**: наша задача - найти слово в словаре. Если данное нам слово начинается на букву "А", то было бы логичней двигаться ближе к началу книги, а не брать постоянно половину от рассматриваемого множества страниц, что делает бинарный поиск

Чтобы брать в учёт величину элемента, индекс серединного элемента следует вычислять по следующей формуле:
$$mid =\left[l + (r-l)*\frac{ value - a_{l}}{a_{r}-a_{l}}\right]$$
где $l, r$ - границы рассматриваемого отрезка, $value$ - искомый элемент, $a_{l}, a_{r}$ - элементы массива, находящиеся на позициях $l$ и $r$ соответственно

### 🔸 Почему такая формула?
Разберём по порядку:
$l$ - левая граница рассматриваемого отрезка, выйти за него мы не можем

$r-l$ - разность индексов, то есть количество элементов в рассматриваемом промежутке

$\frac{value-a_{l}}{a_{r}-a_{l}} \in (0,1)$ - соотношение величины искомого числа к величине наибольшего элемента на отрезке(с учётом того, что мы начинаем не с нуля, а с $a_{l}$, поэтому его и вычитаем).

Получается, умножая дробь на количество элементов на отрезке, мы получаем прогноз - примерное расстояние нашего искомого числа от левой границы(но эта левая граница может быть не нулём, поэтому мы её и прибавляем)
## 🔶Реализация
```cpp title="Interpolation Seach"
#include <iostream>
#include <vector>
#include <cmath>
  
int interpolationSearch(std::vector<int>& v, int val) {
	int l = 0, r = v.size() - 1, mid;
	while (r >= l) {
		mid = l + (r-l) * ((val - v[l]) / (v[r] - v[l]));
		if (v[mid] < val) l = mid + 1;
		else r = mid - 1;
	}
	if (mid == v.size() || v[mid] != val) return v.size();
	return mid;
}
  
int main() {
	std::vector<int> v = {0, 2, 3, 5, 10, 11, 12, 17, 20};
	int ind = interpolationSearch(v, 12); // 6
}
```

## 🔶Оценка сложности
### 🔸Time Complexity
В бинарном поиске мы сокращали массив вдвое каждый раз.

В интерполяционном поиске(при равномерном распределении чисел) мы сокращаем рассматриваемый отрезок от $n$ до $\sqrt{ n }$, то есть на каждой итерации мы берём корень от длины рассматриваемого отрезка. **Почему?** Я сам не знаю, это теория вероятностей и закон больших чисел. Пытался что-то понять, сильно понятней не стало, примем как данное

В таком случае после $k$ итераций длина массива будет составлять $n^\left( \frac{1}{2^k} \right)$. Пусть после этих $k$ операций наш рассматриваемый отрезок стал длины 2(можно взять и три, но с двойкой легче считать - в любом случае к этой длине мы рано или поздно придём).
Значит, $$n^{\frac{1}{2^k}}=2\implies \frac{1}{2^k}=\log_{2}{n}\implies 2^k=\log_{n}{2}\implies k=\log_{2}{\log_{2}{n}}$$
Расмотрев два оставшихся элемента за $O(1)$, можем сказать, что всего операций было совершено
**Time Complexity:** $O(k)=O(\log \log n)$
**Но** если элементы не распределены равномерно(например, экспоненциальный рост), мы деградируем до $O(n)$
### 🔸Space Complexity
Ничего нового, $O(1)$
