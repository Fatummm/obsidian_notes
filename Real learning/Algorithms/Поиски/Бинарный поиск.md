#search
англ. - "Binary search"
Условия: **отсортированный набор данных**
**Time Complexity:** $O(\log n)$
**Space Complexity:** $O(1)$ или $O(\log n)$
## 🔶Идея
Представим, у нас есть отсортированный массив чисел $a[1\dots n]$ и есть число $x$. Как проверить, есть ли число $x$ в массиве $a$(и если оно есть, вернуть его номер)?
Давайте рассмотрим "серединный" элемент массива, то есть $a\left[ \left\lfloor  \frac{n}{2}  \right\rfloor \right]$. 

Если он больше нашего икса, то, раз наш массив отсортирован, очевидно, что наш икс, если он есть, не может быть во второй половине массива(так как серединный элемент больше, то и все элементы правее серединного будут больше икса), и имеет смысл искать его в левой половине.

Иначе, если он меньше икса, то аналогично в силу отсортированности нет смысла искать элемент в левой половине, и мы пытаемся найти в правой.

Ну и если наш икс и серединный элемент совпадают, то поздравляю, мы нашли исходный элемент - возвращаем индекс(или итератор) и заканчиваем выполнение.

Таким образом, выполнив всего одно сравнение, мы "сузили" нашу область поисков в два раза, выбрав либо правую, либо левую половину. Надеюсь, очевидно, что с оставшимися половинами мы можем провернуть аналогичный трюк
## 🔶Реализация
### 🔸Итеративный поиск
Самый популярный, на рекурсивный даже не смотрите
```cpp title="Iterative Binary search"
#include <iostream>


template <typename Iter, typename Value>
Iter binarySearch(Iter first, Iter last, Value val) {
	ssize_t mid,
	l = 0,
	r = last - first;
	while (r >= l) {
		mid = (r + l) / 2;
		if (*(first + mid) > val) r = mid - 1;
		else if (*(first + mid) < val) l = mid + 1;
		else return (first + mid);
	}
	return last;
}

int main() {
	int a[] = {1, 4, 6, 12, 13, 17, 23, 31, 32, 56};
	auto it = binarySearch(a, a + 10, 31);
	std::cout << *it << '\n'; // 31
}
```
### 🔸Рекурсивный поиск
Мне лень было его нормально писать, поэтому так
```cpp title="Recursive Binary Search"
#include <iostream>
  
ssize_t recursiveBinarySearch(int * a, ssize_t left, ssize_t right, int value) {
	if (right < left) return -1;
	int mid = (left + right) / 2;
	if (a[mid] > value) 
	return recursiveBinarySearch(a, left, mid - 1, value);
	else if (a[mid] < value) 
	return recursiveBinarySearch(a, mid + 1, right, value);
	return mid;
}

  

int main() {
	int a[] = {1, 4, 6, 12, 13, 17, 23, 31, 32, 56};
	auto index = recursiveBinarySearch(a, 0, 10, 31);
	std::cout << index << '\n'; // 7
}
```
## 🔶Оценка сложности
Каждая итерация бинарного поиска сокращает рассматриваемую область вдвое. В худшем случае(когда элемента нет в массиве) мы дойдём до области размера 1, а затем 0. Сколько раз нам нужно делить область вдвое, чтобы прийти к её размеру 1? Ответ - $O(\log n)$.
Значит,
**Временная сложность:** $O(\log n)$

**Что по памяти?**
В случае итеративного поиска мы заводим всего три дополнительные переменные, так что $O(1)$
В рекурсивном количество вызовов рекурсии совпадает с количеством итераций бинарного поиска - соответственно, $O(\log n)$
## 🔶Lower bound и Upper bound
### 🔸Идея
Почти всегда рассматриваемого элемента нет в данном массиве. Но иногда нам нужно найти не сам элемент, а наиболее близкий к нему по значению. В таком случае применяются так называемые `lower_bound` и `lower_bound`. Обе они работают практически как бинарный поиск
### 🔸Lower bound
Данная разновидность возвращает указатель на первый встретившийся элемент в массиве, **не меньший** искомого.
```cpp title="lower_bound"
#include <iostream>
#include <vector>
  
int lower_bound(std::vector<int>& v, int val) {
	int l = 0, r = v.size() - 1, mid = 0;
	int ans;
	while (r >= l) {
		mid = (r + l) / 2;
		if (v[mid] == val) { // если нашли элемент, равный искомому, идём влево, чтобы найти первый такой
			ans = mid;
			r = mid - 1;
		}
		else if (v[mid] < val) l = mid + 1; // идём в правую половину
		else { // идём в левую половину
			ans = mid;
			l = mid + 1;
		}
	}
	if (l == v.size()) ans = v.size();
	return ans;
}
  
int main() {
	std::vector<int> v = {1, 2, 3, 5, 5, 5, 6, 7};
	int ind = lower_bound(v, 8); // 8
}
```
### 🔸Upper bound
Тут же мы возвращаем указатель(индекс) на минимальный элемент, **больший искомого**.
```cpp title="upper_bound"
#include <iostream>
#include <vector>
  
int upper_bound(std::vector<int>& v, int val) {
	int l = 0, r = v.size() - 1, mid = 0;
	int ans;
	while (r >= l) {
		mid = (r + l) / 2;
		if (v[mid] <= val) l = mid + 1; // идём в правую половину
		else { // идём в левую половину
			ans = mid;
			r = mid - 1;
		}
	}
	if (l == v.size()) ans = v.size();
	return ans;
}
  
int main() {
	std::vector<int> v = {1, 2, 3, 5, 5, 5, 6, 7};
	int ind = upper_bound(v, 5); // 6
}
```
## 🔶Бинарный поиск по ответу
Довольно часто перед нами стоит задача немного другого поиска - требуется найти наименьший(наибольший) элемент, который удовлетворяет определённым условиям. 
**Пример1:** чтобы выставить балл зелёной волны, работникам приёмной комисси ВШЭ нужно узнать наибольший балл вступительных испытаний, который не попал в порог бюджетных мест

**Пример2 (Коровы и стойла):** На прямой расположены $n$ стойл (даны их координаты на прямой), в которые необходимо расставить $k$ коров так, чтобы минимальное расстояние между коровами было как можно больше. В ответ записать получившееся расстояние между коровами(решение, как и статью про бинпоиск по ответу, можно найти [здесь](https://ru.algorithmica.org/cs/interactive/answer-search/))
Гарантируется, что $1 < k < n$. 

Тогда **идея** решения подобных задач состоит в следующем - рассматриваем множество ответов - от наименьшего числа до наибольшего, и используем на нём бинарный поиск. На каждой итерации берём соответственно предполагаемый ответ, и проверяем, удовлетворяет ли он нашим условиям. Если да, то идём в левую половину(если ищем минимальный, удовлетворяющий нашим условиям)
## 🔶Встроенный в C++ бинарный поиск
В языке C++, в заголовочном файле `<algorithm>`, существует три функции, реализующих алгоритм бинарного поиска:
1. `std::binary_search(Iter start, Iter end, Value val)` - ищет элемент в отсортированном контейнере, и если его найдёт, то вернёт `true`, иначе - `false`
2. `std::lower_bound(Iter start, Iter end, Value val)` - работает по принципу `lower_bound`
3. `std::upper_bound(Iter start, Iter end, Value val)` - аналогично
   Соответственно, первая функция возвращает тип `bool`, две остальные - `Iter`, итератор
### 🔸 Ограничение на итераторы
Нужный итератор должен быть как минимум *RandomAccessIterator*(подробнее см. [[Итератор в C++]]). Это ограничение следует из того, что мы должны быстро вычислять `mid` - за $O(1)$
### 🔸 lower_bound и upper_bound в multimap и multiset
В контейнерах `std::multimap<T>` и `std::multiset<T>` есть методы верхней и нижней границы. Они нужны, например, чтобы найти все элементы с одинаковым ключом - они будут лежать в промежутке между `multiset.lower_bound(value)` и `multiset.upper_bound(value)`.
