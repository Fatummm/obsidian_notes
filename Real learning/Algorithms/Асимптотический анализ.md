## Введение
Представим, что у нас есть два разных алгоритма, записанных на одном и том же языке программирования и при этом решающих одну и ту же задачу

Появляется **проблема** - мы не знаем, как оценить эти два алгоритма и сказать, какой из них лучше.

Возможное **решение** - замерять время выполнения алгоритма на одних и тех же входных данных.
Теперь новая *проблема* - у разных устройств разные мощности и особенности, соответственно, на одном ПК первый алгоритм может показать результаты лучше второго, но на другом ПК он может сильно проиграть второму $\implies$ идея о временном рассчёте не самая хорошая.

Теперь попробуем понять, сколько *операций* совершает каждый алгоритм. Довольно часто(почти всегда) это количество зависит от количества входных данных.

Будем считать каждую бинарную операцию за единичное действие
### Example.
Допустим, наша задача тривиальна - нам нужно сохранить в памяти $n$ чисел.
**Формат входных данных:** Сначала число $n$ - количество чисел, затем - $n$ чисел.
**Решение:** в зависимости от того, что от нас хотят - вывести числа в терминал или записать в какой-нибудь файл, наша программа будет иметь тот или иной вид, но общие черты будут одинаковыми:

```CPP title="basic"
#include <iostream>

int main() {
	// ...
	int n; std::cin >> n;
	int a[1000] // we know that n <= 1000
	for (int i = 0; i != n; ++i) {
		std::cin >> a[i]
	}	
}
```


Именно поэтому было принято решение оценивать алгоритмы не по времени, а **асимптотически**.
