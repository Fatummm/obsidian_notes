## 🔶 Верхний уровень стека TCP/IP - прикладной(application)
Он объединяет три уровня эталонной модели OSI - *прикладного*, *уровня представления* и *сессионного*. Таким образом, он осуществляет взаимодействие между сетью и пользователем/сторонними приложениями

Выполняет следующие функции:
- Позволяет приложениям использовать сетевые службы
- Обеспечивает удалённый доступ к файлам и базам данных
- Осуществляет пересылку электронной почты
- Отвечает за передачу служебной информации
- Предоставляет приложениям информацию об ошибках
- Формирует запросы к нижним уровням

## 🔶 HTTP/HTTPS
### 🔸 Описание
**HTTP(Hyper-Text Transport Protocol)** - протокол передачи информации, используемый для получении информации с веб-сайтов. Использует модель "клиент-сервер" - есть сервер, отвечающий на запросы, и клиенты, формирующие и отправляющие эти запросы.

Так как нам нужно, чтобы все данные дошли до нас в корректном виде и полностью, перед отправкой/получением HTTP-запросов и ответов, устанавливается TCP-сессия

**Использует порт 80**

**Примеры клиентов(веб-браузеры)**: Internet Explorer, Mozilla Firefox, Google Chrome
**Примеры серверов(серверное ПО)**: Apache, IIS, nginx
### 🔸 Пример HTTP-запроса
![[HTTP-request.png]]
**В первой строчке** видим ключ запроса - **GET**. То есть мы хотим получить информацию с сервера. 
После ключа стоит "/" - означающий, что мы запрашиваем корневую страницу по **URL** - Uniform Resource Locator - идентификатору какого-либо ресурса в сети.
Затем видим **HTTP/1.1** - версия протокола

**В последней строчке** сидит хост - IP-адрес сервера, к которому мы обращаемся

### 🔸 HTTPS
**HTTPS(Hyper-Text Transport Protocol Secure)** - расширение протокола HTTP, существенное отличие - данные передаются в зашифрованном виде. Для этого поддерживает криптографические протоколы.

**Использует порт 443**
## 🔶 DNS
### 🔸 Описание
**DNS(Domain Name System)** - система доменных имён, как видно из названия. Хранит информацию о доменах - соотносит имена и адреса сайтов. База данных поддерживается с помощью иерархичной модели.

**Использует порт 53**
### 🔸Пример работы
![[DNS resolving.png]]
Предположим, мы набрали в браузере адрес `ru.wikipedia.org`. Браузер ищет соответствие этого адреса IP-адресу в файле _hosts_. Если файл не содержит соответствия, то далее браузер спрашивает у сервера DNS: «какой IP-адрес у `ru.wikipedia.org`»? Однако сервер DNS может ничего не знать не только о запрошенном имени, но и даже обо всём домене `wikipedia.org`. В этом случае сервер обращается к корневому серверу — например, 198.41.0.4. Этот сервер сообщает — «У меня нет информации о данном адресе, но я знаю, что 204.74.112.1 является ответственным за зону `org`.» Тогда сервер DNS направляет свой запрос к 204.74.112.1, но тот отвечает «У меня нет информации о данном сервере, но я знаю, что 207.142.131.234 является ответственным за зону `wikipedia.org`.» Наконец, тот же запрос отправляется к третьему DNS-серверу и получает ответ — IP-адрес, который и передаётся клиенту — браузеру.

### 🔸 nslookup
Утилита **nslookup(name system look up)** - позволяет обратиться к DNS-серверу и узнать у него информацию об имени или IP-адресе

**Пример использования**
![[nslookup example.png]]

### 🔸 Файл hosts
Есть в любой ОС. Выполняет функцию DNS-сервера, но контролируется администратором компьютера, а также имеет **приоритет выше** над DNS-сервером.

**Example**
Если у вас в файле написано, что сайту habrahabr.ru соответствует IP адрес, который на самом деле соответствует google.ru, то, соответственно, открывать он будет google, а не habrahabr.

**Расположение:**
- Windows: windows\system32\drivers\etc\hosts
- Unix-подобные системы: /etc/hosts
## 🔶 DHCP
### 🔸Описание
**DHCP(Dynamic Host Configuration Protocol)** - протокол динамической настройки узла. Позволяет узлам динамически получать IP-адреса и другие параметры для корректной работы. По сути позволяет добавлять новые устройства в сеть без их ручной настройки.

При помощи DHCP можно обеспечить полный контроль над IP адресами: создавать отдельные пулы для каждой подсети, выдавать адреса в аренду, резервировать и т.д.

**Использует UPD порты 67 и 68**

### 🔸 Пример работы
1. Клиент-устройство подключается к сети, отправляет широковещательный запрос (DHCP Discover) с просьбой предоставить сетевые настройки
2. DHCP-сервер, обнаружив запрос, отправляет предложение (DHCP Offer) с доступными сетевыми параметрами
3. Клиент выбирает одно из предложений и отправляет подтверждение (DHCP Request), чтобы зарезервировать выбранные настройки
4. Сервер подтверждает запрос (DHCP ACK), предоставляя клиенту выбранные настройки
## 🔶 POP3 / IMAP
### 🔸 Описание
**POP3(Post Office Protocol Version 3)** - протокол почтового отделения версии 3. Используется для получения почтовых писем с сервера.

Работает по принципу "загрузи и удали" - клиент заходит на сервер в поисках писем для него. Если находит таковое, то загружает его к себе на устройство и ставит отметку об его удалении на сервере.

**Использует порт 110**
### 🔸 POP3S
**POP3S(Post Office Protocol Version 3 Secure)** - аналог расширенной версии HTTPS у HTTP. Использует криптографический протокол SSL(Secure Sockets Layer).

Так как нам важно, чтобы данные полностью дошли до клиента, перед отправкой запросов и ответов устанавливается **TCP-сессия**

**Использует протокол 995**
### 🔸 IMAP
**IMAP(Internet Message Access Protocol)** - тоже протокол доступа к электронной почте. Сложнее, чем POP3. Основное отличие - клиент, заходя на сервер, не удаляет почту, а копирует себе на устройство

Так как нам важно, чтобы данные полностью дошли до клиента, перед отправкой запросов и ответов устанавливается **TCP-сессия**

**Использует протокол 143**

## 🔶 SMTP
### 🔸 Описание
**SMTP(Simple Mail Transfer Protocol)** - простой протокол передачи почты. Используется для загрузки почтовых писем на почтовый сервер

**Использует порт 25**
## 🔶 Telnet
### 🔸Описание
**Telnet(terminal network)** - сетевой терминал. Применяется для отображения текстового интерфейса + управления ОС. Используется для настройки почти любого сетевого устройства и в целом получения доступа к нему(можно по консольному кабелю, но не всегда под рукой + по Telnet необязательно находиться рядом для получения доступа к оборудованию)

**Использует порт 23**

## 🔶 SSH
### 🔸 Описание
**SSH(Secure Shell)** - позволяет управлять ОС, как и **Telnet**. Отличие, как может быть видно из названия, в том, что он шифрует весь трафик и передаваемые пароли. Шифруется при помощи алгоритма Диффи-Хеллмана

## 🔶 FTP
### 🔸 Описание
**FTP(File Transfer Protocol)** - протокол передачи файлов. Работает по модели "клиент-сервер".

TCP-сессия, естественно

**Использует порт 21**
### 🔸 Пример работы
Попробуем подключиться к открытому ftp-серверу test.rebex.net и скачать оттуда файл `readme.txt`:
1. Открываем терминал и вводим `ftp test.rebex.net`. 
2. Затем нас просят ввести логин и пароль, вводим `demo` и `password`
3. Введём `dir`, чтобы увидеть список доступных файлов
4. Скачаем файл `readme.txt` командой `get readme.txt`
Готово, теперь в домашней директории у нас есть файл `readme.txt`

## 🔶 TFTP
### 🔸Описание
**TFTP(Trivial File Transfer Protocol)** - упрощённый аналог FTP. Работает по UDP, т. е. не требует установления сессии. Не требует аутентификации и авторизации, достаточно знать и иметь IP-адрес.

**Использует порт 69**
